# Decisions

Dated decisions for this repo, newest last.

- 2026-11-09: created from the standard repo starter kit.
- 2026-11-09: built at the owner's request ("payload-plugin-maintenance", the name he chose) from the first site's hand-written switch. Admin global plus a proxy gate read over REST; MIT like the other general Payload plugins. Stays private until the owner OKs going public and publishes 0.1.0 by hand.
- 2026-11-11: the `access` default fails closed: only users of the admin collection (`admin.user`) may change the switch. Before, any signed-in account could, members of other auth collections included. Sites relying on the old default must pass the option. From the plugin access sweep.
- 2026-11-13: moved to the ExtantApe GitHub organization and to `@extantape/payload-plugin-maintenance` at the same version (0.2.0). EXTANT APE owns its reusable tools and licenses them to the platform. The old npm name is deprecated with a pointer, and GitHub redirects the old repository URL. This is the first plugin to move; the others follow the same steps.
- 2026-11-27, **confirmed by the owner** ("Stay open (Recommended)"): a site with no valid configured address stays open, with a startup warning, and `SITE_MAINTENANCE=on` still closes it.
- 2026-11-27, build choices made along with that. The owner's confirmation above doesn't cover them. The gate reads the switch only from a configured site address (`origin`, then `SITE_MAINTENANCE_ORIGIN`, then Vercel's system variables, which come from the platform and so need no change on most Vercel sites). The request, redirects included, stays on that address. An unusable `apiRoute` (one that would send the request elsewhere) is treated like a missing address. The warning is logged when the gate is built, except with a custom `read`. Staying open matches the rule for a switch that has never been read. The alternative, closing the site, would take down working sites that upgrade without the setting. The cost of staying open: a self-hosted site with the box ticked reopens on upgrade until the address is set, so the changelog and README say so. The change would ship as 0.3.0 because it is a breaking change.
